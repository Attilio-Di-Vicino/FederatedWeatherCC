# FederatedWeatherCC

Federated learning framework for distributed multi-station weather forecasting using Transformer and Crossformer architectures. This repository accompanies the eScience paper extending [Di Vicino et al., CEUR-WS Vol-4124, BigHPC2025/ITADATA2025](https://ceur-ws.org/Vol-4124/paper51.pdf).

Developed at the University of Naples "Parthenope" as part of the [Hi-WeFAI](https://www.hiwefai-project.org) project, funded by the National Center ICSC (CUP E63C22000980007).

---

## Overview

Eight meteorological stations operated by the University of Naples "Parthenope" act as federated clients. Each station trains a local model on its own data — raw sensor readings are never shared. A central server aggregates model weights using FedProx to produce a global forecast model for outdoor temperature (TempOut).

Key design decisions:

- **Warm-start FL**: the global model is initialised from a centralised checkpoint before federated rounds begin, making local adaptation the goal of FL rather than learning from scratch
- **Per-station temporal windowing**: sliding windows are built within each station's timeline before concatenation, preventing cross-station data leakage
- **Quality-driven feature selection**: columns with >75% missing data (SolarRad, UV) and zero-variance columns (BarTrend) are dropped; Barometer (8.3% missing) is retained and imputed

## Feature Set

| Column           | Role       | Notes                                     |
|------------------|------------|-------------------------------------------|
| `station_id`     | Feature    | integer station identifier (1–8)          |
| `Barometer`      | Feature    | atmospheric pressure; 8.3% NaN → imputed |
| `HumOut`         | Feature    | outdoor relative humidity                 |
| `RainDay`        | Feature    | cumulative daily rainfall                 |
| `WindSpeed`      | Feature    | instantaneous wind speed                  |
| `WindSpeed10Min` | Feature    | 10-minute average wind speed              |
| `wind_sin`       | Feature    | sin(WindDir) — encoded before resampling  |
| `wind_cos`       | Feature    | cos(WindDir) — encoded before resampling  |
| **`TempOut`**    | **Target** | outdoor temperature                       |
| `BarTrend`       | Dropped    | 100% zeros, zero variance                 |
| `SolarRad`       | Dropped    | 78.9% missing                             |
| `UV`             | Dropped    | 85.2% missing                             |
| `RainRate`       | Dropped    | 99% zeros — unsuitable regression target  |

## Getting Started

### 1. Clone and set up

```bash
git clone https://github.com/Attilio-Di-Vicino/FederatedWeatherCC
cd FederatedWeatherCC
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 2. Build the processed dataset

Raw data lives **outside** the repository. Pass one or both root directories to the ingestion script:

```bash
# Single data root
python src/utils/data_ingestion.py /path/to/raw_data \
    --output data/processed_data/dataset.csv

# Multiple roots (old + new structure, merged automatically)
python src/utils/data_ingestion.py /path/to/raw_data /path/to/raw_data_2025 \
    --output data/processed_data/dataset.csv
```

### 3. Centralised training

```bash
cd src/model/transformer && python train.py
# or
cd src/model/crossformer && python train.py
```

### 4. Federated learning

The server must be started before clients. It waits for all 8 clients before beginning round 1. The server loads the centralised checkpoint as the initial global model (warm start) — run centralised training first.

```bash
# Terminal 1 — server
cd src/model/transformer   # or crossformer
python fl_server.py

# Terminals 2–9 — one client per station
python fl_client.py 1 localhost:8082
python fl_client.py 2 localhost:8082
python fl_client.py 3 localhost:8082
python fl_client.py 4 localhost:8082
python fl_client.py 5 localhost:8082
python fl_client.py 6 localhost:8082
python fl_client.py 7 localhost:8082

# ... through station 8
python fl_client.py 8 localhost:8082
```

Crossformer server listens on port **8082**; Transformer on **8082**.

## Configuration

Both models share the same `config.yaml` structure. Key parameters:

```yaml
data:
  input_window: 20       # hours of history as encoder input
  output_window: 2       # hours ahead to forecast
  target_cols:
    - TempOut

training:
  local_epochs: 2        # local training epochs per FL round
  rounds: 20             # federated communication rounds

model:
  input_dim: 8           # must equal len(feature_cols)
  d_model: 64
  nhead: 4
  num_layers: 2
  dropout: 0.1
```

## Results

All metrics on MinMax-scaled [0,1] data. Skill Score = `1 − MSE_model / MSE_baseline` (baseline: always predict zero).

### Centralised training

| Model       | MAE    | RMSE   | Skill  |
|-------------|--------|--------|--------|
| Transformer | 0.1433 | 0.1838 | 0.6956 |
| Crossformer | 0.1227 | 0.1639 | 0.7578 |

### Federated learning — Crossformer (FedProx, warm-start, 20 rounds)

| Round | MAE    | RMSE   | Skill   |
|-------|--------|--------|---------|
| 1     | 0.1808 | 0.2419 |  0.3206 |
| 5     | 0.2200 | 0.2835 |  0.0848 |
| 10    | 0.2276 | 0.2906 |  0.0832 |
| 15    | 0.2895 | 0.3458 | −0.2709 |
| 20    | 0.2749 | 0.3342 | −0.1943 |

### Federated learning — Transformer (FedProx, warm-start, 20 rounds)

| Round | MAE    | RMSE   | Skill   |
|-------|--------|--------|---------|
| 1     | 0.3263 | 0.3731 | −0.6565 |
| 5     | 0.3901 | 0.4191 | −1.0467 |
| 10    | 0.4162 | 0.4449 | −1.1790 |
| 15    | 0.4262 | 0.4457 | −1.2208 |
| 20    | 0.3845 | 0.4049 | −0.9673 |

The Crossformer outperforms the Transformer in both settings, consistent with the previous paper. Performance degradation over FL rounds reflects non-IID data heterogeneity across stations — an open challenge discussed in the paper.
